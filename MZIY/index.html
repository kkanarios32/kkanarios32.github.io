Card. The three units and the one data path [MZIY]

  • August 10, 2026
  • Kellen Kanarios

What are the three units inside a TPU TensorCore (TPU), and what is the data path from HBM to compute?

Answer
  • MXU — matrix multiply on a systolic array. Nearly all of the FLOPs.
  • VPU — elementwise ops (ReLU, add, mul) and reductions.
  • VMEM — an on-chip scratchpad in the TensorCore, like L1/L2 but far larger (~128 MiB on v5e) and programmer-controlled rather than a cache.
The path is HBM \(\to \) VMEM \(\to \) VREGs \(\to \) MXU/VPU \(\to \) VMEM \(\to \) HBM. Nothing computes directly out of HBM. All of it is pipelined — the copies overlap with MXU work, so the array never stalls waiting on memory.

    Definition. Matrix Multiply Unit (MXU) [OGCRP]

    • May 22, 2026
    • Kellen Kanarios

    A core component of the TPU architecture responsible for performing matrix multiplication via a weight stationary Systolic array.

    • \(128 \times 128\) — 16,384 multiply accumulate units, each multiplying and adding in one cycle. v6e/Trillium widens the array to \(256 \times 256\), i.e. 65,536.
    • The native op is one bf16[8,128] @ bf16[128,128] -> f32[8,128] every 8 cycles, or about \(5e13\) bf16 FLOPs/s per MXU at 1.5 GHz. A v5e chip has enough MXUs to reach ~\(2e14\).
    Remark. The side length is fixed in hardware, so every dimension has to be tiled down to it and any axis shorter than it is padded up to it, wasting the FLOPs spent on the padding. The order is
    1. Tiling the matrix to load from HBM to VMEM.
    2. Compiler tiles from VMEM to \(128 \times 128\) tiles to load into the MXU.

    Definition. Vector Processing Unit [OGCRN]

    • May 22, 2026
    • Kellen Kanarios

    A core component of the TPU architecture responsible for elementwise operations.

    • 2D SIMD execution, where each of 1024 sites execute same program in lockstep.
    • Each site contains 4 ALUs, enabling 4096 FLOPs.
    • Fed a 8x128 Vector Register in one cycle.
