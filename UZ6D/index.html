Card. The batch size is the intensity [UZ6D]

  • August 6, 2026
  • Kellen Kanarios

For a bf16 matmul \([B, D] \times [D, F] \to [B, F]\), give the FLOPs, bytes, intensity, and the resulting rule of thumb.

Answer \(\text {FLOPs} = 2BDF\) and \(\text {bytes} = 2BD + 2DF + 2BF\) — both operands loaded, the output written, two bytes apiece — so \[\mathrm {Intensity} = \frac {BDF}{BD + DF + BF}\] With \(B \ll D, F\) the \(DF\) term dominates the denominator and the intensity collapses to \(BDF / DF = B\). The whole rule of thumb is that the batch size is the intensity: a matmul is compute-bound once the per-replica batch exceeds \(240\) tokens on TPU (\(\approx 295\) on H100, from \(9.89 \times 10^{14} / 3.35 \times 10^{12}\)). Three caveats. \(B\) counts tokens, not sequences. The threshold is per replica — sharding scales FLOPs and bandwidth together, so it applies to each copy of the weights (Data parallelism). And tiling changes the byte count once the matmul is large enough that the operands no longer fit.

    Definition. Matrix Multiply Unit (MXU) [OGCRP]

    • May 22, 2026
    • Kellen Kanarios

    A core component of the TPU architecture responsible for performing matrix multiplication via a weight stationary Systolic array.

    • \(128 \times 128\) — 16,384 multiply accumulate units, each multiplying and adding in one cycle. v6e/Trillium widens the array to \(256 \times 256\), i.e. 65,536.
    • The native op is one bf16[8,128] @ bf16[128,128] -> f32[8,128] every 8 cycles, or about \(5e13\) bf16 FLOPs/s per MXU at 1.5 GHz. A v5e chip has enough MXUs to reach ~\(2e14\).
    Remark. The side length is fixed in hardware, so every dimension has to be tiled down to it and any axis shorter than it is padded up to it, wasting the FLOPs spent on the padding. The order is
    1. Tiling the matrix to load from HBM to VMEM.
    2. Compiler tiles from VMEM to \(128 \times 128\) tiles to load into the MXU.

    Definition. Vector Processing Unit [OGCRN]

    • May 22, 2026
    • Kellen Kanarios

    A core component of the TPU architecture responsible for elementwise operations.

    • 2D SIMD execution, where each of 1024 sites execute same program in lockstep.
    • Each site contains 4 ALUs, enabling 4096 FLOPs.
    • Fed a 8x128 Vector Register in one cycle.

        Data parallelism [QPFO]

        • May 22, 2026
        • Kellen Kanarios

        A form of parallelism where the model is replicated across multiple devices and performed on different data.

        • Data sharding: data is split across multiple devices i.e. 32 samples and 8 devices results in 4 unique samples per device.
        • Parameter replication: on each device, we need to replcicate the model parameters to run the forward pass for the unique samples.
        • Gradient aggregation: backward pass we need to perform an all-reduce to sum and average the gradients across devices. This is automatically done by @nnx.jit.
