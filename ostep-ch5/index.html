Exercise 1. fork() copies the address space, not the variable

  • May 12, 2026
  • Kellen Kanarios

Write a program that calls fork(). Before forking, set a variable — say x — to 100. What is its value in the child? What happens when parent and child both change it?

Solution

The child gets a copy of the parent's address space, \(x\) included. Each subsequent write lands in that process's own copy, so neither sees the other's change.

Exercise 2. A file descriptor survives the fork

  • May 12, 2026
  • Kellen Kanarios

Open a file with open() and then fork(). Can both child and parent use the returned descriptor? What happens when they write to the file concurrently?

Solution

Both have access to the same descriptor. Concurrent writes can in principle interleave, but in my runs whichever process was scheduled first always finished writing before the other started — plausibly a scheduling artifact rather than a guarantee.

Exercise 3. Ordering child before parent without wait()

  • May 12, 2026
  • Kellen Kanarios

Write a program where the child prints "hello" and the parent prints "goodbye", with the child always printing first. Can you do it without calling wait() in the parent?

Solution

Reusing the shared file from the previous exercise: have the child write a value, and have the parent spin in a while loop until it reads that value back. It works, and it is miserable — which is presumably why wait() exists.

Exercise 4. What wait() returns, and what it does in the child

  • May 12, 2026
  • Kellen Kanarios

Now use wait() in the parent to wait for the child. What does it return? What happens if you call wait() in the child?

Solution

It returns the pid of the child that died. Called in the child — which has no children of its own — it returns \(-1\) immediately.

Exercise 5. Why exec() has so many variants

  • May 12, 2026
  • Kellen Kanarios

Write a program that calls fork() and then some form of exec() to run /bin/ls. Try the variants — execl(), execle(), execlp(), execv(), execvp(), execvP(). Why are there so many spellings of one call?

Solution

The suffixes are a small matrix of three independent choices. The v family takes a variable-size argument vector where the l family takes a fixed argument list. The e family takes an explicit environment — the list of environment variables the new program will see — instead of inheriting the caller's. The p family resolves the program name against PATH, the way a shell does, instead of requiring a path.

Exercise 6. When waitpid() beats wait()

  • May 12, 2026
  • Kellen Kanarios

Rewrite the previous program using waitpid() instead of wait(). When is waitpid() the one you want?

Solution

When a parent has several children. wait() returns on whichever dies first; waitpid() lets you name the child you care about.

Exercise 7. printf() after closing STDOUT in the child

  • May 12, 2026
  • Kellen Kanarios

Create a child process that closes standard output (STDOUT_FILENO). What happens if the child then calls printf()?

Solution

Nothing prints from the child. The parent's stdout is a separate descriptor and is untouched, so it still prints.

Exercise 8. Connecting two children with pipe()

  • May 12, 2026
  • Kellen Kanarios

Create two children and connect the standard output of one to the standard input of the other using pipe().

Solution

It worked only once I added fflush() — the writer's output was sitting in stdio's buffer rather than in the pipe. Whether that is required in general or an artifact of how I structured the writer, I am not sure.
