Definition. AllGather [VSDZ]

  • August 12, 2026
  • Kellen Kanarios

An AllGather gets resources from all devices onto one device. In TPU's Ring topology, this is done in \(\frac {N}{2}\) hops via each TPU sending its shard to the neighboring chip.

Assuming we have \(X\) shards and the total bytes is \(N\), then each chip must send \(\frac {N}{X}\) bytes. If we have an ICI bandwidth of \(W_{\text {ICI}}\), then for each chip to send to its neighbor will be \[T_{1\text { hop}} = \frac {N}{X\cdot W_{\text {ICI}}}\] Now each chip must send across \(X\) hops, which gives \(T = X\cdot T_{1\text { hop}} = \frac {N}{W_{\text {ICI}}}\).This does not change if we use the bi-directional bandwidth because then we have \(2N\) bytes but only need to send at most \(\frac {X}{2}\) hops!

Remark. A super fun trick from [scaling-book, Ex 3.2]: If you have an unused replicated dimension, then you can shard the replicated axis and perform an AllGather over both dimensions to double your bandwidth!

Card 1. AllGather costs the same at any device count [RBEJ]

  • August 12, 2026
  • Kellen Kanarios

AllGather: signature, mechanism, and cost?

Answer

Signature \([A_X, B] \to [A, B]\) — it removes a subscript, reassembling shards so every device on that axis holds a full copy. It can drop just one of several axes: \(A[I_{XY}, J] \to A[I_Y, J]\).

Mechanism: pass each shard around the ring, \(N-1\) hops in one direction or about \(N/2\) bidirectionally.

Cost, when bandwidth-bound: \(T = V / W_{\mathrm {ici}}\) on bidirectional bandwidth, or \(V / (W_{\mathrm {ici}} \cdot N_{\mathrm {axes}})\) across several mesh axes. The takeaway is that this is independent of the device count \(X\) — each hop sends \(V/X\) bytes but you make \(X/2\) hops. Only array size and link bandwidth matter.

Latency-bound regime: about \(1\mu \mathrm {s}\) intrinsic cost per hop, so \(T = \max (T_{\min } \cdot \sum _i |X_i| / 2,\; V / (W \cdot N_{\mathrm {axes}}))\). On v5e (\(4.5e10\) unidirectional) anything under ~45 kB is latency-bound.

Card 2. Gather before, or reduce after [JO4V]

  • August 12, 2026
  • Kellen Kanarios

Sharded matmul, case 2: one multiplicand has a sharded contracting dimension, \(A[I, J_X] \cdot B[J, K] \to C[I, K]\). Which primitive, and what is the alternative?

Answer AllGather the sharded input first, then matmul locally: \(\mathrm {AllGather}_X(A[I, J_X]) \to A[I, J]\), then \(A[I, J] \cdot B[J, K] \to C[I, K]\). You cannot just multiply the local shards, because the sum over \(J\) is split across \(X\) and each device holds only a partial sum. The alternative is to treat it like case 3: do the local partial matmul and AllReduce or ReduceScatter the result. That shards the FLOPs but usually costs more comms. For \(X[B,D] \cdot Y[D_X,F]\), the gather moves \(2DF\) bytes and the reduce moves \(2 \cdot 2BF\), so the reduce path wins roughly when \(D > 2B\). Rare in practice, though — the other input is usually sharded along the same axis anyway, as under FSDP.

Card 3. A mesh axis may appear only once [QBBA]

  • August 12, 2026
  • Kellen Kanarios

Sharded matmul, case 4: both multiplicands have a non-contracting dimension sharded along the same mesh axis, \(A[I_X, J] \cdot B[J, K_X]\). Why is this invalid, and how do you resolve it?

Answer A mesh axis may appear at most once in a sharding. Writing \(C[I_X, K_X]\) would give shard \(i\) only the \((i,i)\) block — the block diagonal. The off-diagonal blocks of \(C\) exist nowhere, so the result is unrecoverable. The fix is to AllGather one of the two inputs along \(X\) first, so that \(X\) appears once in the output:
  • \(\mathrm {AllGather}_X(A) \to A[I, J]\), giving \(C[I, K_X]\).
  • \(\mathrm {AllGather}_X(B) \to B[J, K]\), giving \(C[I_X, K]\).
Which one you pick is decided by the sharding the downstream ops want.
