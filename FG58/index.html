Card. op_name is the trace path back to Python [FG58]

  • August 22, 2026
  • Kellen Kanarios

How do you map an HLO instruction back to Python?

Answer The metadata field: 
%dot_general.0 = f32[8,4]{1,0} dot(%param_0, %param_1), lhs_contracting_dims={1},
    rhs_contracting_dims={0}, metadata={op_name="jit(f)/dot_general" stack_frame_id=2}
op_name is the JAX trace path, not just a label: nested transformation scopes — jit, jvp, transpose, vmap, remat — separated by slashes, ending in the jaxpr primitive that emitted the op. So it says more than a source line. It says which transformation produced this instruction: an op under jvp(...) is forward-mode work, one under transpose(...) is the backward pass (A grad jaxpr is the forward program plus its transpose). The source location is indirect. Current XLA interns it: stack_frame_id indexes a StackFrames table printed at the top of the module, which chains through FileLocations to FileNames and FunctionNames. You resolve the id there rather than reading a filename off the instruction, and the chain gives you the whole call stack, not one frame. This is the path that survives the passes that scramble names (The numeric suffix means nothing). The MLIR equivalent is the location (Locations are the provenance of an op).
